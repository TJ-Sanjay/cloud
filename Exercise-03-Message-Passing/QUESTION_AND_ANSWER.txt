EXERCISE 3 — MESSAGE PASSING AND DISTRIBUTED MUTUAL EXCLUSION
=============================================================

QUESTION
--------
Task 1: Create a server that supports multiple socket clients so processes can send and receive messages.
Task 2: Implement the Ricart–Agrawala, Token Ring, and Centralized Coordinator algorithms for mutual exclusion. Processes request access to a critical section, and the algorithm must ensure only one process enters it at a time using request/grant/release messages.

AIM
---
Demonstrate client/server message passing and compare three distributed mutual-exclusion approaches.

WHERE TO DO THIS
----------------
Use Ubuntu with Python 3. The chat demo uses TCP sockets. The three mutual-exclusion programs are deterministic local simulations so their message order and safety property are easy to observe on one VM.

TASK 1 — CHAT
-------------
Terminal 1:
python3 chat_server.py

Terminal 2 (and any additional terminals):
python3 chat_client.py
Enter messages. The server broadcasts each message to connected clients. Type /quit to disconnect.

TASK 2A — RICART–AGRAWALA
-------------------------
python3 ricart_agrawala.py
The program simulates timestamped requests, immediate/deferred replies, and entry into the critical section. It prints the event order and confirms that only one process is in the critical section at a time.

TASK 2B — TOKEN RING
--------------------
python3 token_ring.py
The token is passed around the logical ring. Only the process holding the token can enter the critical section.

TASK 2C — CENTRALIZED COORDINATOR
---------------------------------
python3 centralized_coordinator.py
The coordinator grants one request at a time and queues other requests until the current process releases the critical section.

COMPARISON
----------
- Ricart–Agrawala: processes exchange timestamped REQUEST/REPLY messages; a process waits for replies from peers.
- Token Ring: possession of a unique token grants access; token circulation can be delayed by a failed node/link.
- Centralized Coordinator: a coordinator serializes requests; the coordinator can become a single point of failure.

TROUBLESHOOTING
---------------
- For chat, start the server first and use 127.0.0.1 for same-VM tests.
- If the port is occupied, stop the old server with Ctrl+C.
- The three mutual-exclusion scripts are protocol simulations, not networked multi-host implementations. They are suitable for demonstrating protocol logic; use actual distributed sockets and failure handling for a production implementation.
