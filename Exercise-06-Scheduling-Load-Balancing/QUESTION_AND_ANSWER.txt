EXERCISE 6 — TASK SCHEDULING AND LOAD BALANCING IN A CLOUD ENVIRONMENT
=========================================================================

QUESTION
--------
Part 1: Use a cloud/VM service to schedule tasks automatically.
Part 2: Configure a load balancer to distribute incoming traffic across multiple VM instances and maintain availability.
Optional: Extend scheduling with task prioritization and dependencies.

AIM
---
Automate recurring jobs and distribute web requests among multiple backend VMs.

WHERE TO DO THIS
----------------
Clone the cloud repository on an Ubuntu VM and work in the Exercise-06-Scheduling-Load-Balancing folder. Run scheduling commands inside an Ubuntu VM. Run the backend service on two Ubuntu VMs and HAProxy on a separate VM (or combine roles if host resources are limited).

PART 1 — CRON TASK SCHEDULING
-----------------------------
1. Make the script executable:
   chmod +x scheduled_task.sh
2. Run it manually:
   ./scheduled_task.sh
3. Create a log directory:
   mkdir -p "$HOME/cloud-lab-logs"
4. Find your home directory:
   echo "$HOME"
5. Open your personal cron table:
   crontab -e
6. Add this line, replacing USER with your Ubuntu username and ensuring the repository is at /home/USER/cloud:
   */1 * * * * /home/USER/cloud/Exercise-06-Scheduling-Load-Balancing/scheduled_task.sh >> /home/USER/cloud-lab-logs/scheduled_task.log 2>&1
7. Wait two minutes and inspect:
   tail -n 10 ~/cloud-lab-logs/scheduled_task.log
8. Remove the cron entry after testing by running crontab -e and deleting that line.

PART 2 — LOAD BALANCING
-----------------------
1. Run backend_server.py on each backend VM: python3 backend_server.py
2. Find each backend VM's private IP with hostname -I.
3. On the load-balancer VM install HAProxy:
   sudo apt update
   sudo apt install -y haproxy
4. Copy haproxy.cfg to /etc/haproxy/haproxy.cfg after backing up the original file.
5. Replace sample IP addresses in the configuration with your backend VM IPs.
6. Validate and restart:
   sudo haproxy -c -f /etc/haproxy/haproxy.cfg
   sudo systemctl restart haproxy
7. Test several requests:
   for i in $(seq 1 8); do curl -s http://LOAD_BALANCER_PRIVATE_IP/; done
The backend hostname in the responses should demonstrate traffic distribution.

OPTIONAL ADVANCED SCHEDULING
----------------------------
For a queue-based example, Celery can schedule jobs and Redis can act as the broker. Install these only if required by your lab instructions: python3 -m pip install celery redis. Run Redis as a service and configure a Celery worker/beat process; do not expose Redis publicly.

FILES
-----
- scheduled_task.sh: cron job.
- backend_server.py: test HTTP backend.
- haproxy.cfg: round-robin load balancer.

RESULT/EVIDENCE
---------------
Show the cron entry, log timestamps from at least two runs, HAProxy configuration validation, and repeated curl results from the load balancer.

TROUBLESHOOTING
---------------
- Cron uses a minimal environment: use absolute paths and redirect output to a log.
- Check cron status with systemctl status cron.
- If a backend is down, confirm HAProxy health checks mark it unavailable.
- Do not leave recurring test jobs installed after the exercise.
